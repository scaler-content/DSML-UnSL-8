DBSCAN
Discovering clusters of any shape

DBSCAN post read

Clusters as dense regions, and the honest ability to say "this point belongs to no group": the method behind a ranked review queue for ShopSphere's fraud team.

The problem

The accounts that belong nowhere

A message from the fraud team landed on Vikram's phone, and he forwarded it to Anjali. Imran, the fraud team lead, joined the call the next morning.

"We have two kinds of problem accounts: resellers who buy in bulk to resell elsewhere, and scripted accounts that click and visit in robotic patterns. They don't behave like any real shopper. But your segmentations are no use to me. The GMM puts those accounts into a segment and says it is 90% sure. The Ward tree gives some of them tiny branches and attaches others to big groups. Last year's K-Means dragged its centres toward them. Nothing ever says 'this account fits nowhere'."

The accounts he cares about do not sit in neat round clouds. Many lie along thin trails where clicks and visits grow together in unnatural proportions.

"I have two reviewers. I can look at a few hundred accounts a week, not thousands. I need a list of the most unusual accounts, ranked. And ideally the method should also tell us which regular customers form real, dense groups, whatever their shape."

Every method used so far assigns every point to a group. Imran wants a method that starts from density: where lots of customers behave alike, there is a group, and where a customer has no company, they belong to no group at all. That method is DBSCAN.

2 · The idea

Clusters are dense regions

DBSCAN stands for Density-Based Spatial Clustering of Applications with Noise. It is built on one picture:

A cluster is a region where points are packed closely together, separated from other clusters by regions where they are sparse.
eps (ε)The radius of the neighbourhood around a point.
min_samplesThe number of points (counting the point itself) that must lie within eps for the neighbourhood to count as dense.

Three kinds of points

TypeDefinition
CoreHas at least min_samples points (itself included) within distance eps. It sits in a dense area.
BorderIs not core, but lies within eps of at least one core point. It is on the edge of a cluster.
×NoiseNeither core nor border: no dense neighbourhood and no core neighbour, so it belongs to no cluster (label −1).

Once eps and min_samples are fixed, every point's type is fully determined by the data.

3 · Density connection

How clusters grow

Knowing the point types is not enough. DBSCAN must decide which points form the same cluster.

  • A point q is directly density-reachable from a core point p if q is within eps of p.
  • Two points are density-connected if a chain of core points, each within eps of the next, links them. A border point can hang off the end of a chain.
  • A cluster is a maximal set of density-connected points.

The algorithm

  1. Pick an unvisited core point and start a new cluster with it.
  2. Add all points within eps of it. Whenever a newly added point is itself core, add its neighbours too. Keep expanding until no new points can be reached. Border points are added but do not expand the cluster.
  3. Pick another unvisited core point and repeat.
  4. Points never reached from any core point are noise (label −1).

Clusters grow like a spreading stain, so they can take any shape: as long as dense stepping stones connect them, the cluster continues.

Trace the algorithm

Density connection. Points 0 and 3 are 3 apart, far more than eps, yet they end up in the same cluster, linked through the chain of core points 1 and 2. That is why DBSCAN clusters can have any shape. Point 10 is never reached, so it stays noise.
Code: DBSCAN from scratch (about 20 lines) 
def dbscan_scratch(X, eps, min_samples):
    n = len(X)
    D = squareform(pdist(X))
    neighbours = [np.where(D[i] <= eps)[0] for i in range(n)]          # includes the point itself
    is_core = np.array([len(nb) >= min_samples for nb in neighbours])
    labels = np.full(n, -1)                                            # -1 = noise until reached
    cluster = 0
    for i in range(n):
        if labels[i] != -1 or not is_core[i]:
            continue                                                   # start only from unlabelled core points
        labels[i] = cluster
        queue = [i]
        while queue:                                                   # grow the cluster
            p = queue.pop()
            for q in neighbours[p]:
                if labels[q] == -1:
                    labels[q] = cluster                                # core or border, both join
                    if is_core[q]:
                        queue.append(q)                                # only core points keep expanding
        cluster += 1
    return labels, is_core

On the lecture's 132-point dataset, this hand-written version agrees with scikit-learn exactly: same core points, same noise points, and cluster agreement (ARI) of 1.0. The only possible difference is a border point lying within reach of two clusters, which joins whichever cluster reaches it first. That is the only non-deterministic part of DBSCAN.

5 · Hyperparameters

Choosing eps and min_samples

DBSCAN has only two hyperparameters, but they matter a great deal.

min_samples

  • Rule of thumb: at least d + 1, where d is the number of features, and often about 2d.
  • Larger values need more evidence to call a region dense, which suits noisier data and gives fewer, more conservative clusters.
  • ShopSphere has 6 features, so a good starting point is 2d = 12.

eps: the k-distance plot

With min_samples fixed, a point is core when its min_samples-th nearest neighbour (counting itself) lies within eps. So:

  1. For every point, compute the distance to its min_samples-th nearest neighbour (its k-distance).
  2. Sort these distances and plot them.
  3. Dense regions have small k-distances; isolated points have large ones. The curve rises slowly then bends sharply upward. The value at the bend is a good eps: below it most points are core, above it points sit in sparse regions (likely noise).

k-distance plot and its effect

Blobs + noise dataset (simulated live). Move eps along the curve and watch the clustering on the right. A knee is rarely razor sharp, so treat the knee as a starting point.

Code: k-distance and the knee heuristic 
MIN_SAMPLES = max(2 * n_feat, n_feat + 1)                  # 12 for 6 features
nn = NearestNeighbors(n_neighbors=MIN_SAMPLES).fit(X)
dist, _ = nn.kneighbors(X)                                  # column 0 is the point itself (distance 0)
kdist_each = dist[:, -1]                                    # distance to the MIN_SAMPLES-th point, counting itself
kdist = np.sort(kdist_each)

def knee_value(kd):
    """Point of the sorted curve farthest below the straight line joining its two ends."""
    x = np.linspace(0, 1, len(kd))
    y = (kd - kd.min()) / (kd.max() - kd.min())
    return kd[int(np.argmax(x - y))]

  • Small eps: most points fail the density test, so lots of noise and many small clusters.
  • Large eps: everything becomes density-connected, so noise vanishes and clusters merge into one.
  • Larger min_samples demands more neighbours, so noise rises and clusters shrink.

Noise does not mean fraud. An account can be far from everyone for harmless reasons, for instance a very big genuine spender. The list is a review queue, not a verdict, and reviewers' findings should feed back into the process. Also remember that DBSCAN flags points by their lack of close neighbours in all features together, not by any single feature, so a one-feature explanation (such as a z-score) can mislead; reviewers need the combination as well.

Placing new accounts

DBSCAN has no predict. A simple, defensible rule that mirrors the algorithm's own logic:

  1. Find the new account's nearest core point.
  2. If that core point is within eps, the account gets that core point's cluster.
  3. Otherwise, flag it as noise for review.

Try it in the playground above (Place a new account). To test the rule on real data, hold out 20% of customers, fit on the rest, and compare noise shares: if new customers are flagged at a rate similar to the training customers, the rule behaves consistently, and a sudden jump in the flagged share is itself an alarm that behaviour (or the bots) has changed.

Code: assign new customers 
def assign_new(db, X_train, X_new, eps):
    core_pts = X_train[db.core_sample_indices_]
    core_lab = db.labels_[db.core_sample_indices_]
    d = cdist(X_new, core_pts)
    nearest = d.argmin(axis=1)
    reachable = d[np.arange(len(X_new)), nearest] <= eps
    return np.where(reachable, core_lab[nearest], -1)
7 · Scoring

Evaluating a clustering that contains noise

1Do not score noise as a clusterNoise is "not in a cluster". Including label −1 in a silhouette calculation treats scattered points as a tight group and distorts the score. (In this run it gave 0.261; the older script's version of this mistake gave 0.006.)
2Use each metric under its own nameThe Dunn index (higher is better) and the Davies-Bouldin index (lower is better) are different metrics.

ShopSphere's result is one cluster plus noise, so silhouette and Davies-Bouldin, which need at least two clusters, are undefined. This is common on real data. The useful questions are practical: how many accounts were flagged, are they really different from the rest, and can the reviewers handle the volume?

ok = ~noise_mask

8 · Honest limits

Where DBSCAN struggles

1. Varying densities

DBSCAN uses one eps and one min_samples for the whole dataset. If the data has tight clusters and loose ones, no single eps suits both: a small eps shatters the loose cluster into noise, and a large eps merges the tight clusters.

Two tight clusters and one loose one

Three groups of 250 points (spreads 0.3, 0.3 and 1.6), min_samples = 8. Slide eps and watch the trade-off. Simulated live.

  • Small eps: the tight clusters come out well, but much of the loose cluster is classed as noise.
  • Medium eps: a compromise that rarely serves everyone.
  • Large eps: the loose cluster is captured, but the two tight clusters merge, since the gap between them is smaller than eps.

HDBSCAN (a hierarchical extension of DBSCAN, with OPTICS as another relative) removes the single global eps by building a hierarchy over many eps values, and is the usual remedy for varying density.

2. High dimensions

DBSCAN depends on "close". In many dimensions, distances concentrate: the nearest and farthest neighbours are almost the same distance away, so there is no gap for eps to sit in. For 500 random points, the relative spread (farthest − nearest) ÷ nearest from one point:

Distance contrast collapses with dimension

Hover or tab to a bar.

The usual remedy is to reduce dimensions first (for example with PCA), then run DBSCAN on the reduced data, checking that the result is stable.

3. Cost

Each point needs a range query: find all points within eps. Done naively, that is a scan of all points, so O(n²) total. With a spatial index (KD-tree or ball tree) a range query is about O(log n) in low dimensions, so the total is about O(n log n). In high dimensions the index stops helping and cost drifts back toward O(n²).

4. Sensitivity and no predict

Both were seen above: small changes in eps changed the cluster count and noise share, and new points need your own assignment rule.

10 · Wrap-up

Key takeaways and the clustering toolkit

  • DBSCAN defines clusters as dense regions separated by sparse ones. It needs eps (radius) and min_samples (the count that makes a neighbourhood dense, itself included).
  • Core points have at least min_samples points within eps. Border points are not core but lie within eps of a core point. Noise is neither, with label −1. All three are fully determined by the data and the two parameters.
  • Clusters grow by density connection: chains of core points. That is why DBSCAN finds any shape and needs no K.
  • min_samples is typically at least d + 1, often about 2d. eps comes from the k-distance plot (the knee), checked against a grid of settings, because results are sensitive.
  • Evaluate carefully: do not score noise as a cluster, and do not mix up the Dunn and Davies-Bouldin indices. With one cluster plus noise, judge by the noise share and the profile of the flagged points. Noise is a review queue, not a verdict.
  • Limitations: one global eps (varying densities need HDBSCAN or OPTICS), distances that lose meaning in high dimensions (reduce first), sensitivity to hyperparameters, and no predict (use the nearest-core-point rule).
  • Cost: about O(n log n) with a spatial index in low dimensions, drifting toward O(n²) otherwise.

Which method for which question?

Start from the question (probabilities? nested levels? shapes and outliers? speed at scale?), then from the shape of the data, then check the result with several lenses: metrics, pictures, stability, and above all domain sense.
